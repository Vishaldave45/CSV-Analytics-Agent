# Evaluation Contract Audit & Data Flow Trace

## 1. Current Result Flow
The current flow for agent execution and evaluation is:

```text
GoldenTestCase
      ↓
AgentRuntime.run(question)
      ↓
LangGraph Engine (Router → Planner → Tool Node → Memory/Explainer)
      ↓
Tool Node execution (Python Engine or Deterministic Engine)
      ↓
AnalysisResult creation
      ↓
analysis_result_to_checkpoint() (offloads payload to RuntimeArtifactStore)
      ↓
AgentState["last_analysis_result"] stored as AnalysisResultCheckpoint (dict)
      ↓
AgentRuntime._hydrate_runtime_state() attaches payload back to dict artifacts
      ↓
EvaluationRunner receives hydrated AgentState dict
      ↓
[BREAKAGE POINT] EvaluationRunner checked `isinstance(analysis_res, AnalysisResult)`
      ↓
`isinstance` evaluated to False (since `last_analysis_result` is a `dict`)
      ↓
Fell into fallback block creating `AnalysisResult(artifacts=[])`
      ↓
Deterministic Evaluator checked `actual_artifacts` → empty set!
```

## 2. Canonical AnalysisResult Contract
The canonical application result model is defined in `src/csv_analytics_agent/results/models.py`:

```python
class AnalysisResult(BaseModel):
    status: AnalysisStatus
    narrative: str
    artifacts: list[AnalysisArtifact] = Field(default_factory=list)
    execution_time_ms: float | None = None
    source: str = "agent"
    question: str | None = None
    dataset_hash: str | None = None
    metadata: dict[str, Any] = Field(default_factory=dict)
    error_type: str | None = None
    error_message: str | None = None
```

## 3. Canonical Artifact Contract
The canonical artifact model is defined in `src/csv_analytics_agent/python_engine/models.py` (`PythonArtifactType`) and `src/csv_analytics_agent/results/models.py` (`AnalysisArtifact`):

### Supported Artifact Types
- `text` (`PythonArtifactType.TEXT`): Text summaries or markdown tables.
- `scalar` (`PythonArtifactType.SCALAR`): Numerical calculations (e.g. total revenue = 756000.0).
- `table` (`PythonArtifactType.TABLE`): Tabular data structures / DataFrames.
- `interactive` (`PythonArtifactType.INTERACTIVE`): Interactive Plotly visualizations.
- `image` (`PythonArtifactType.IMAGE`): Static matplotlib/seaborn images.
- `diagram` (`PythonArtifactType.DIAGRAM`): Mermaid or graph visual diagrams.
- `file` (`PythonArtifactType.FILE`): Downloadable exports (CSV/Excel).
- `dataframe` (`PythonArtifactType.DATAFRAME`): Raw pandas DataFrames.

## 4. Where Artifacts Are Lost & Why `actual_artifact_types` Became Empty
In `src/csv_analytics_agent/evaluation/runner.py`:
- `runtime.run()` returns `AgentState` where `last_analysis_result` is a hydrated dictionary (`AnalysisResultCheckpoint` format).
- `EvaluationRunner` evaluated:
  ```python
  if isinstance(analysis_res, AnalysisResult):
      last_result = analysis_res
      for art in analysis_res.artifacts:
          actual_artifacts.append(art.artifact_type.value)
  else:
      # Dropped into fallback creating empty artifacts!
      last_result = AnalysisResult(..., artifacts=[])
  ```
- Because `analysis_res` was a `dict` (and not a Pydantic `AnalysisResult` class instance), `isinstance` returned `False`.
- The runner created a dummy `AnalysisResult` with `artifacts=[]`, causing `actual_artifacts` to be recorded as `[]` for every single test case!

## 5. Tool-Selection Failure Analysis
Out of 35 golden test cases:
- **Planner Accuracy**: 77.1% (27/35 correctly planned).
- **Planner Failures (22.9%)**:
  1. **Unnecessary Python Selection**: For basic aggregation/filtering/grouping (e.g. `001: What is total revenue?`, `004: Show revenue by category`), the Planner LLM selected `python_analysis` instead of `deterministic_engine`.
  2. **Multi-Step Repeated Python Calls**: On complex queries (e.g., `006`, `007`, `022`, `023`, `024`), the Planner repeatedly invoked `python_analysis` up to 6 times before terminating.

---

## 6. Repeated Tool-Call Root Cause
When the Planner invokes `python_analysis`, the Python Execution Engine returns `stdout` and artifact metadata.
However, in multi-turn or multi-step graph loops, the Planner receives the tool message without an explicit final narrative signal or explicit `FINISH` directive, causing the LLM to call `python_analysis` repeatedly until `max_iterations` is hit.

---

## 7. Visualization Artifact Flow
Plotly figures generated by `python_analysis` or `visualization_engine` are converted to dictionary specs (`{"data": [...], "layout": [...]}`).
They are stored in `AnalysisArtifact` with `artifact_type=PythonArtifactType.INTERACTIVE` and payload containing the Plotly JSON object.

---

## 8. Frontend / Backend Contract Compatibility
The frontend component (`streamlit_app/components/agent_response.py` & `artifact_renderer.py`) expects artifacts formatted as `AnalysisArtifact` with `artifact_type` matching `"scalar"`, `"table"`, `"interactive"`, `"text"`, `"image"`.
The backend `AnalysisResultCheckpoint` dictionary matches this structure 1:1.

---

## 9. Recommended Architectural Fixes

1. **Hydration / Extraction Fix in `src/csv_analytics_agent/evaluation/runner.py`**:
   Support both `AnalysisResult` instances AND `dict` / `AnalysisResultCheckpoint` dictionaries when extracting artifacts and building `last_result`.

2. **Tool Selection vs. Artifact Assertion Separation**:
   In `evaluate_behavior()`, separate:
   - **Artifact Correctness**: Whether expected artifacts (`scalar`, `table`, `interactive`, `text`) were produced.
   - **Tool Selection Correctness**: Whether expected engine (`deterministic` vs `python`) was chosen.

3. **Planner Prompt Policy Adjustment (Future)**:
   In `prompts/planner/system.md`, enforce strict instructions to prefer `deterministic_engine` for simple aggregate/group/filter/sort queries.
